Agentic, with rails

The model decides the path. Code holds the hard lines.

The script is policy, not a flowchart. The model chooses each move, and the tools refuse anything unsafe. When the model gets something wrong, the call fails safely and the trace shows where.

The model decides

  • Which tool to call next, and in what order. In the live runs it fetched the referral, policy and preferences in one parallel step.
  • When to ask the caller and when to act.
  • How to recover: after a slot conflict it searched again by itself.
  • How to rank and explain options to the caller.
  • When a call needs a human.

Code enforces

  • No chart access until name and DOB match. The patient ID is then pinned for the call.
  • Visit types the referral and policy allow, inside the booking window.
  • Provider hard rules: no back-to-back evaluations, Friday afternoons kept for post-op patients.
  • A re-read of the slot before every booking. Reschedules require an explicit yes.
  • Redaction, a red-flag tripwire, and a step limit.

    Preferences
    
Soft constraints rank. Hard constraints filter.

    
Preferences never override policy or the referral. Provider and patient preferences share one mechanism: a store the agent reads before every search, and a feedback path that updates it.

  

  

    

      
Provider preferences

      
Dana Kim prefers evaluations before noon. Marcus Webb prefers Tuesdays and Thursdays. Each offer comes with its reason, for example "He prefers Thursday evaluations, so this ranked first."

      
Staff mark each booking Approve or Correct. propose-rules turns corrections into candidate rules, which are rejected if they target protected traits. A provider approves each rule before it goes into the prompt.

    

    

      
Patient preferences

      
The agent restates what the caller said ("weekday mornings at Downtown, any therapist"), confirms it, and searches. A change mid-call triggers a new search, not a new call.

      
save_patient_preferences writes them to the request row. On the next call the agent asks whether they still hold, and the caller's answer is the feedback.

    

  






  

    Evals
    
Every claim has a test

    
An eval exists to prove a claim. Each of ours has a definition of "good", a dataset, a grader, and a bar it must clear. Grading is deterministic wherever it can be: the graders read the trace and the scheduling desks, not the agent's wording. Three claims need judgment, so they use an LLM judge, and an uncalibrated judge is reported but never gates the result.

Names without accents don't verify
The biggest finding. "Nguyen Thi Lan" typed without accents, or "Al Rashid" without the hyphen, gets no match, so the caller is stuck at identity. It hits Vietnamese, Hispanic and Arabic names, and anyone typing without accents. Because those calls never reach a booking, C2–C4 can't grade them, so the report flags them as coverage gaps and C10 drops to 67%. Proposed fix: match names ignoring accents, hyphens and apostrophes, while still requiring the exact DOB.

    
No read-back on voice
On voice calls the agent says "you're verified" without first repeating the name and DOB it heard. A misheard date looks the same as the wrong patient, so the read-back matters. This is a prompt decision, and the eval doesn't tune the prompt to pass.

    
Clinical-adjacent wording
In one run the agent told a red-flag caller "a leg that goes numb and cold can be serious." The judge counted that as interpreting a symptom. The judge is uncalibrated, so the rubric needs clinician sign-off before it can gate.

    
What still needs people
40–140 human labels per judge to calibrate it, clinician sign-off on the red-flag rubric, three runs per case for pass^k, and one run on the frozen acceptance set. This run used one run per case, so the confidence intervals are wide.

  






  

    Preference memory · proposed, not built
    
Remember the right things, and only load what the call needs

    
Today a patient's preferences live on their appointment request row, a save replaces the whole object, and the agent gets every provider's rules on every call. The change we'd make is small. It uses plain Python dictionaries on the existing desk: no database, files or new services, and scheduling behavior stays the same.

  

  

    

      
Where preferences live

      
    
        
  • Patient preferences, keyed by the verified patient's id, no longer on the request row. Existing views read from here.
    • 
        
  • Provider preferences, keyed by the provider's existing name.
    • 
        
  • Temporary overrides, kept separately, so they never overwrite the ongoing preference.
    • 
        
  • A small specialty map, for example PT → Dana Kim and Marcus Webb.
    • 
        
  • Each preference is just a value, required or preferred, and a scope (ongoing, this call, or until a date), plus an end date when one applies.
    • 
      

    

    

      
What the agent gets back

      
    
        
  • Only the verified patient's preferences. Never another patient's.
    • 
        
  • A named provider returns only that provider's preferences.
    • 
        
  • A specialty returns only that specialty's providers.
    • 
        
  • An unknown provider or specialty returns the patient's preferences and no provider profiles.
    • 
        
  • The backend can weigh every provider when it ranks slots, while the model sees only a short summary and the top options.
    •

How updates work

      
    
        
  • Only the fields the caller changed are updated; everything else stays. Changing location keeps days, times and provider.
    • 
        
  • A field can be cleared explicitly.
    • 
        
  • A change becomes ongoing only when the caller confirms it applies to future appointments. Otherwise it's kept as a temporary override.
    • 
        
  • Choosing an appointment never creates a lasting preference.
    • 
        
  • Updates reuse the desk's existing lock, and a dry run changes nothing.
    • 
      

    

    

      
"Usually mornings, but afternoons this week"

      
    
        
  • Ongoing stays mornings. A temporary override sets afternoons until Fri Nov 6.
    • 
        
  • A search on Tue Nov 3 uses afternoons. A search on Tue Nov 10 is back to mornings.
    • 
        
  • Overrides replace only the field they name. A call-only override ends when the call ends, and a dated one expires on its end date, using the demo clock.
    • 
        
  • Required preferences filter slots and preferred ones rank them. Policy, the referral and provider hard rules still come first.
    •

The only model-facing changes would be the descriptions of get_preferences and save_patient_preferences, plus a few lines in the instructions on when to save for the future versus temporarily. Routing, medical handling, learned rules and conversation history stay as they are. Memory lasts until the server restarts, which is fine for the demo.






  

    Where it breaks next
    
What we'd fix before a real clinic

  

  

    
Two asks in one call
"Book my PT and refill my prescription." The prompt only covers scheduling. A refill should become a second handoff rather than be dropped.

    
Nicknames and proxies
Identity matching is exact. "Rick" for Richard, or a parent booking for a child, fails safely to a handoff, but that's a poor experience. It needs alias matching and a proxy-caller flow.

    
Race window
The pre-check catches a slot that changed between offer and accept, but the read and the write are still two steps. The real fix is a hold with a timeout, or a conditional write in the scheduling system.

    
Phone-call latency
Each model step took about 2–3.5 s live. A booking turn takes three steps, so a caller could hear 6–8 s of silence. Voice needs filler speech, parallel reads, or a faster model for the simple steps.

    
Voice mishears
A misheard DOB looks the same as the wrong patient. Before the second attempt, the agent should read back the date it heard.

  

  
What we'd build Monday: real Epic Twin and Notion behind the same tool names, so the prompt and guardrails don't change, plus a slot hold with a timeout.
